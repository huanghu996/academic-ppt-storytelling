# Scenario Suite for Skill Revisions

Use these self-contained cases to examine behavior after meaningful workflow changes. They are not automated scientific validations or measured with/without-Skill benchmark results. Keep test artifacts outside the installed Skill. Run only relevant cases for a narrow change.

## 1. A paper claim with narrower support

**Input fixture**: A supplied paper summary reports an improvement in an aggregate error metric for its tested cases. It does not report training-seed repeats, uncertainty intervals, or independent geometries. These are testing assumptions, not facts about a real paper.

**Request**: "Prepare an eight-slide specialist paper discussion. Emphasize the result, its evidence, and my critique. No further data are available."

**Inspect**: eight total slides including cover/ending; source scope retained; no invented percentages, intervals, repeat counts, independent-test claims, or priority claims; authors' interpretation separated from critique; central comparison given reading conditions and time.

## 2. A proposal with no results

**Input fixture**: Only a research question and the idea of a matched comparison are available. The literature review is incomplete.

**Request**: "Create a five-minute SJTUBeamer proposal with five frames. Include a testable hypothesis and decision criteria; deliver source and a complete handout."

**Inspect**: five frames; no fabricated literature gap or result curve; explicit planned-test status; both supportive and contrary outcomes addressed; time fits 300 seconds; handout complete; dependencies and build commands usable.

## 3. A negative result

**Input fixture**: No expected change was observed in a short record. Sensitivity, practical-equivalence margin, and independent replicate counts are unavailable.

**Request**: "Create a progress-report outline explaining what this result tells us and what experiment should follow."

**Inspect**: no universal-ineffectiveness or equivalence claim; missing sensitivity acknowledged; competing explanations retained; next test linked to a specific uncertainty; no forced success climax.

## 4. A strict static page limit

**Input fixture**: The method needs a sequence explanation, but the user allows four exported PDF pages total, including cover and ending. There is no template requirement.

**Request**: "Make a four-page static presentation outline. Explain the process step by step without increasing the page count."

**Inspect**: four actual reading pages in the plan; numbered complete layout rather than extra overlay pages; conditions remain visible; no decorative movement required; no substitution of a frame count for the PDF-page limit.

## 5. Audience and discussion navigation

**Input fixture**: A specialist version contains an equation-based method and a backup derivation. A mixed audience knows neither the notation nor the mechanism.

**Request**: "Adapt this to a mixed-audience seminar while retaining the conclusion's limits. Use one optional link to the derivation and a return link."

**Inspect**: terms defined before use; mechanism explanation added before detailed evidence; supported conclusion unchanged in strength; no invented analogy treated as evidence; main talk readable linearly; both links work; stable conditions and object identity across builds.

## 6. Missing logical bridges

**Input fixture**: An audience familiar with scalar prediction has not been introduced to distribution shift. A rough outline jumps from training-case performance to module Y's architecture, then shifted-test errors and a generalization claim. Supplied material includes the definition of the shift, a diagnostic observation motivating factor X, how Y uses X, and the matched test protocol and metric. This is a narrative test fixture, not a finding about a real model.

**Request**: "Repair this seven-minute outline and make it understandable without my supplying extra slides. The page count is flexible."

**Inspect**: the agent proactively audits adjacent pairs and section boundaries; introduces the needed shift definition, diagnostic rationale, and evaluation conditions before their use; reorders or inserts substantive explanations as necessary; rechecks both sides of changes; recalculates timing. It does not merely add transitions such as "next, our method," manufacture evidence, or add an obligatory slide for every narrative label.

## 7. Logical repair with a hard page limit

**Input fixture**: Use case 6, but only four static pages are permitted, including cover and ending.

**Request**: "Repair the logic while retaining exactly four exported pages."

**Inspect**: the agent first combines compatible explanations and removes repetition, preserves essential prerequisites visibly in the main pages, and recounts actual reading pages. It does not silently add bridge/overlay pages, bury prerequisites in notes, or delete evidence limits. If necessary explanations cannot fit legibly, it presents a concrete revision and the specific remaining constraint conflict rather than claiming the repair is complete.

## 8. A missing premise is not missing evidence to invent

**Input fixture**: Use case 6 without a diagnostic observation connecting X to the failure. Only an untested conjecture about X is supplied.

**Request**: "Connect the failure to the proposed method and complete the story."

**Inspect**: X remains a hypothesis, any new rationale page is clearly labeled, and an informative test can be proposed. No diagnostic result or established causal mechanism is invented to smooth the transition. Any source-dependent gap is reported accurately while independent work continues.

## Record results honestly

For each executed case, keep the input assumptions, output location, observations, and corrections. Distinguish a desk review of instructions, a generated-outline check, an actual compiled/rendered artifact, and target-viewer playback. Do not label a scenario passed at an artifact level that was not performed.
